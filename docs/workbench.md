# Local Workbench and evidence-only Ask

This feature branch extends ARQUILO with an optional standard-library browser
interface and an independent question mode. The task scheduler, mandatory reviews,
existing model/provider defaults and release version are not replaced. This is a
supervised development preview, not a new release or a sandbox certification.

## Start the interface

From your installed ARQUILO checkout:

```sh
python3 -B arquilo.py workbench --workdir /path/to/project --todo-file tasks.md
```

Windows PowerShell (choose your installed Python 3.11+ interpreter):

```powershell
py -3.11 -B .\arquilo.py workbench --workdir 'C:\Projects\Demo' --todo-file tasks.md
```

Use the exact URL printed by the command. It binds only to `127.0.0.1`; the default
port is 8765, and `--port 0` asks the OS to choose a free port. The credential is in
a URL **fragment**, not a query parameter. The page moves it to session storage and
removes it from the address bar. Treat the printed link as a local secret. There
is no LAN/public-server option, external JavaScript, font CDN or telemetry.

The server verifies Host, Origin, request framing, JSON content type, and a bearer
token on every API read/write. Cross-origin requests, duplicate JSON keys, unsafe
paths, oversized bodies and arbitrary additional arguments are refused. Static
HTML contains no project data. Project text is inserted as text, never executable
HTML. This is local application protection, not multi-user/hostile-host isolation.

## Edit and validate plans

The task table displays saved IDs/statuses. Status words in a file are not proof
that this installation independently reviewed that work.

Enter one task per line and choose **Append to draft**. This preserves the current
Markdown and allocates numeric IDs after the highest existing root. It does not
write the file, renumber old tasks, add executable options or mark work complete.
Numeric/dotted IDs remain the supported runtime syntax.

Edit the Markdown draft, then choose **Validate and preview**. The real task linter
checks it, including dependencies and directives. Review the diff before **Save
reviewed draft**. The server revalidates and checks the loaded SHA-256 revision at
save time. A stale browser cannot overwrite a newer saved plan. BOM and uniform
CRLF line endings are retained. Untouched comments, preambles and fenced examples
are not regenerated by an LLM.

Saves use the controller's OS lock, no-follow atomic writes and private before/after
backups. Saving is refused while this Workbench's run is active or another controller
holds the same plan lock. Ordinary outside editors are detected by revision checks;
this is not a transactional guarantee against an arbitrary same-user program that
ignores locks and races the final filesystem operation.

Owner edits remain **separate from controller adoption**. When an existing journal
differs, inspect the saved changes and explicitly confirm adoption for the next run.
The checkbox is never auto-selected. `--accept-plan-changes` is not a generic repair
for an integrity error. The confirmed hash is checked again under the actual
controller lock before adopting or establishing a baseline.

## Run, pause, cancel, reconnect

**Start / continue saved plan** launches a dedicated, isolated Python worker. It
uses the existing `run_todos.main` and a small worker-local controller adapter; there
is no second scheduler. No shell command, Python executable, environment override
or arbitrary flag can be supplied through the browser.

The browser polls the authenticated state API every second without overwriting an
unsaved draft. The API returns monotonically numbered snapshots, task status, a
bounded console tail, controller events, reviewed-task IDs and terminal exit state.
The console is drained continuously, including long output without newlines; it is
not buffered until process completion. The stored console is capped at 8 MiB and
the displayed tail at 24,000 characters. Truncation is explicit. The normal controller
archives remain separate and are not silently truncated by this UI.

Start requests have persisted idempotency keys: retrying the same request returns
the same job rather than starting another model run. Reusing a key for different
input fails. At most one run and one independent question are active per service.
Another Workbench for the same plan is blocked by a lifetime OS lock.

| Action | Meaning |
| --- | --- |
| Pause at next task boundary | Finish the current task tree and its review, or the whole current parallel batch, then stop before dispatching further work. WAIT loops also observe the request. No OS process suspension and no new `process_stop`. |
| Cancel run | Request cooperative cancellation through the normal stop mechanism, including active subworkspaces. Preserve partial work and any pre-existing stop reason. Remain `cancelling` until the worker actually exits and output collection finishes. |
| Continue | Start a separate invocation using the same authoritative state/budgets and newly confirmed saved plan. No automatic retry, budget reset or replay. |
| Cancel question | Cancel only that question's transport. Do not stop a running task or write a project stop marker. |

After cancellation, inspect partial work and deliberately remove/archive the
`process_stop` marker(s) before continuing. The UI never deletes them on your behalf.
Pause is not success. Exit zero without a valid terminal worker record is not
success. Source status markers do not substitute for controller review evidence.

Closing/reloading the browser does not stop the server or its jobs. Ctrl-C in the
server requests cancellation and waits for the owned workers. If the server dies,
worker pipe EOF requests cancellation; the next server labels unfinished records
`interrupted`. It does not adopt or kill processes using stored PIDs. The existing
controller lock is still authoritative. OS hard kills, native sandbox behavior,
trusted hooks and a hostile same-user process require platform-level testing;
this implementation does not claim universal orphan prevention.

## Evidence-only questions

```sh
python3 -B arquilo.py ask --workdir /path/to/project --allow-provider \
  --depth normal --file README.md "Why was this architecture chosen?"
```

```powershell
py -3.11 -B .\arquilo.py ask --workdir 'C:\Projects\Demo' --allow-provider `
  --depth normal --file README.md 'Why was this architecture chosen?'
```

`--allow-provider` explicitly consents to sending selected evidence and trusting
the configured Codex host/provider. It is not an assertion that the material is
non-confidential. The browser uses a separate explicit consent checkbox. No model
is selected automatically; `--model`, `--reasoning-effort` and `--profile` remain
explicit overrides using the trusted provider configuration.

Ask does **not** run AutoBuild, a mandatory review, a task-status transition or a
Git operation. Unlike the initial draft, it gives Codex **no live project cwd and
no native project-reader tool**. A deterministic local broker supplies bounded
UTF-8 excerpts and permits only validated relative-path/range read requests from
the structured model response. No project script, test, build, macro or shell
command is executed by the broker.

The broker excludes hidden/control directories, symlinks, hardlinks, reparse paths,
binaries, unsupported formats and obvious credential filenames. These exclusions
are not a content/secret scanner. Default selection is a bounded text inventory;
repeated `--file` selections restrict the accessible inventory to those files.
PDF/Office analysis belongs to a separate ingestion pipeline, not this text reader.

Research limits: overview 1 model round, normal 3, deep 5; up to 3 broker requests
per round, 400 lines per excerpt, 512 KiB per file, 160 KiB of supplied excerpt text,
a bounded file/directory inventory, and a 300-second limit per model invocation.
Questions over 16,000 UTF-8 bytes are rejected. An exhausted research budget is an
explicit incomplete/failure result, not a fabricated final answer.

### Codex tool/configuration boundary

Ask alone applies a fixed restrictive preset: disabled shell/unified execution,
web search, multi-agent tools, hooks, apps and related execution surfaces. Before
each model invocation, bounded metadata checks must verify disabled shell and
multi-agent features and no enabled MCP server. Unknown/unverifiable required
metadata fails closed; there is no fallback to ordinary workspace access.

A Codex home containing enabled MCP servers must be restricted by its owner before
using Ask. ARQUILO does not silently rewrite or copy your global configuration or
credentials. See the official [configuration reference](https://developers.openai.com/codex/config-reference/).
Different CLI versions may lack the metadata needed by this strict path even when
normal ARQUILO task execution works. That refusal is intentional, not permission to
turn off the check. The ordinary production/review/Decide paths keep their policies.

Codex runs in a fresh empty cwd with `read-only` and `approval_policy="never"`.
Native tool/unknown events also invalidate the response, including events after a
nominal answer. That event check is **post-event validation, not prevention**.
Trusted provider authentication, proxies, global instructions, managed configuration,
plugins/hooks and the Codex binary remain host trust. Metadata plus restrictive
flags are not proof of zero side effects or OS-level read/network confinement.
Use an approved isolated host/container when those stronger guarantees are needed.

### Evidence, changed files, failures

Each excerpt has a content hash, source ID and line range. A final answer's citation
IDs/ranges must exist in the actually supplied evidence. Undeclared source markers,
unknown files, invalid ranges, duplicate JSON fields, missing response files and
failed/cancelled calls are rejected. Partial terminal text is never promoted to a
successful answer. Source-anchor validation does **not** prove semantic entailment.

File bytes are held stable within the question once read; at completion, changed
or deleted source files are listed. This is a set of versioned file reads, **not an
atomic project snapshot**. Concurrent task work can therefore produce a mixed-time
view, and the answer explicitly says so. Archives retain the exact excerpt evidence
and question/response status separately from the project, in user-private storage.
Codex may separately retain sessions according to its trusted configuration.

## Tests and deployment limits

`tests/test_workbench_ask.py` covers plan integrity/format preservation, HTTP
boundaries, idempotency, concurrency, live output, run/pause/cancel boundaries,
source isolation, citations and failed/partial model output. These are offline
regressions with synthetic model results; some exercise real local HTTP servers
and worker processes. They do not authenticate or use a real model.

```sh
python3 -B -m unittest discover -s tests -v
python3 -B scripts/check_release.py
python3 -B scripts/build_runtime_zip.py
```

Keep the installed runtime outside model-writable production workspaces for
stronger separation. Live model quality, native Windows/macOS sandbox enforcement,
corporate Codex configuration and browser/host combinations still require local
acceptance. No release/tag/merge is implied by this feature branch.
